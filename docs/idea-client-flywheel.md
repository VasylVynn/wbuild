# Ідея: маховик клієнтів — трафік, заявки, база, повторні продажі

> **Дата:** 2026-07-28. **Статус:** ідея-картина, НЕ в роботі (гейт R7 — банерна валідація перша).
> **Походження:** розбір модулів RoxyBo (`competitor-roxybo-analysis.md` §9) → адверсарний
> розбір GPT-ідеї «self-serve прайс + розумна анкета» → питання власника «звідки трафік?»
> і «а якщо база клієнтів?». Поглинає `idea-telegram-two-way-reply.md` (видалений).

---

## 0. Головні правди (фундамент)

1. **Сайт не створює попит.** Нових клієнтів локалці дають рівно три джерела: Google,
   соцмережі, сарафан. Магічної кнопки трафіку немає ні в кого — RoxyBo і Wix продають
   сайти, не відвідувачів. Питання не «як привести на сайт», а «що з трьох джерел МИ
   можемо автоматизувати, чого власник сам не робить».
2. **Повторний продаж > новий трафік.** Флорист — свята щороку, салон — цикл 3–4 тижні,
   СТО — сезони. Повторним продажам трафік не потрібен — потрібна база і привід.
3. **IG DM — не база клієнтів**: не вивантажити, не розіслати, не сегментувати.
   Офлайн-покупець зникає без сліду.
4. **Власник не веде CRM руками.** Будь-яка ручна дисципліна вмирає за тиждень.
   Виживає тільки zero-input база, що наповнюється сама.
5. **Половина інфри вже існує**: таблиця `leads`, центральний TG-бот + webhook
   (`app/api/telegram/webhook/route.ts`), deep-link binding, facts, verticals-as-data,
   force-injected `lead_form` (ІНВАРІАНТ, §5.6 брифу).

## 1. Маховик цілком

```
Відгуки → Google Maps ранжує вище → нові відвідувачі → структурована форма →
заявка в TG власника → швидкий клоуз (reply з TG) → база клієнтів росте →
розсилка (повторні продажі + сарафан «приведи друга») → нові замовлення → нові відгуки…
```

Кожна ланка окремо — дрібна фіча. Разом — замкнене коло, де трафік — вихлоп маховика,
а не окрема невирішувана проблема. Розкручується з першої заявки.

## 2. Ланки

### 2.1 Маховик відгуків — єдиний автоматизований канал НОВОГО попиту

Локальне ранжування в Maps — це передусім відгуки (кількість, свіжість, відповіді).
«Квіти Ірпінь» виграє той, у кого 87 відгуків проти 12. Мікробізнес системно їх не
збирає (соромиться, забуває). Механіка: заявка закрита → наш бот через день питає
клієнта «Все сподобалось? Залиште відгук — 10 секунд» + прямий лінк на форму відгуку
GBP. Кожна заявка докидає палива. Власник сам такого не зробить, IG цього не вміє.
Потребує каналу зв'язку з клієнтом (2.3) і анти-спам обережності.
✅ Валідовано 2026-07-29 (лінк, політика Google, ~20% ваги local pack) —
`partner-discussion-2026-07-29.md` §7.

### 2.2 Структурована анкета per-vertical (конверсія)

- Поля за вертикаллю: флорист — привід/дата/бюджет/кольори/доставка; барбер —
  послуга/майстер/час; СТО — марка/модель/рік/проблема. Заявка приходить готовою:
  «Весілля, 5 червня, до 2000 грн, білі півонії, Печерськ» замість «Привіт».
- **Обов'язкове поле: канал зворотного зв'язку** (телефон / Telegram / IG) — без нього
  «швидкий клоуз» фізично не станеться.
- Адверсарні знахідки (лишаються в силі): кожне поле ріже конверсію — мінімум полів;
  форма фільтрує не лише шум, а й покупців — міряти замовлення/тиждень, не «деталей на
  заявку»; біль живе в IG DM, тож для IG-native вертикалей форма слабша, для
  search-intent (СТО/юрист) — сильна; «прайс/години/адреса на сайті» вже збудовані
  (facts grounding) — новизна лише в полях і позиціонуванні.
- Фіт: verticals = data (`lib/verticals`), lead_form force-injected (§5.6) — зміна на
  дні, не тижні.

### 2.3 Відповідь із Telegram (швидкий клоуз)

Сьогодні заявка — глухий кут: `formatLeadMessage` (`lib/telegram/push.ts:35`) шле
текст і все; власник виходить із TG, набирає номер, клієнт тим часом пише конкуренту.
Speed-to-lead — фактор №1 конверсії локалки.

- Механіка: екран «Дякуємо» → кнопка «Отримати відповідь у Telegram» →
  `t.me/<bot>?start=lead_<token>` (той самий deep-link патерн, що в'яже власника);
  власник робить swipe-reply на повідомленні заявки → webhook мапить
  `message_id → заявка → chat_id клієнта` → пересилає. Обидва у своєму TG, жодних
  нових застосунків.
- Межі: бот не може писати клієнту першим (правило TG) — телефон лишається фолбеком;
  таблиця мапінгу reply→клієнт МУСИТЬ бути скоуплена по власнику
  (один бот на всіх тенантів → інакше крос-тенантний витік).
- ✅ Валідовано 2026-07-29; плюс асиметрія: після /start вікон відправки нема —
  TG = єдиний канал нагадувань без opt-in (IG вимагає Marketing-Messages opt-in).
- Клин: «Сайт кладе клієнта тобі в Telegram — і ти відповідаєш, не виходячи з нього».
- Проти RoxyBo: їхній модуль — AI-бот відповідає відвідувачам (колись збреше про
  ціни); у нас — живий власник, чесність як фіча (дух #44 і grounding фактів).

### 2.4 База клієнтів (актив, zero-input)

- Кожна заявка = структурований контакт. Дедуплікація по телефону: три заявки з одного
  номера = один клієнт з історією. Розділ «Клієнти» замість стрічки «заявок».
- Ручне додавання за 10 секунд (офлайн-покупець) — опція, не вимога.
- 🆕 2026-07-29: третє джерело наповнення — **Instagram DM** (бізнес-акаунт + API):
  авто-картки з переписок, «не губи повідомлення в Instagram» як окремий гострий біль.
  Деталі, ліміти API і вердикти — `partner-discussion-2026-07-29.md` §3.
- Стратегічно: сайт — статичний артефакт («зробив і забув» → чому платити другий
  рік?); база — актив, що росте щотижня → причина платити постійно. Retention-механіка
  підписки.
- Ризики: холодний старт (цінність видно через місяці — retention-фіча, не
  acquisition); згода на маркетинг обов'язкова (ЗУ про захист персданих, чекбокс при
  вході в бота); спам-ліміти TG.
- Конкуренти: Altegio (салони), RemOnline (СТО), KeyCRM — окремі складні платні
  інструменти, які треба вести руками. Наш кут: «база будується сама, поки сайт працює».

### 2.5 Розсилка + сарафан (повторні продажі)

- TG — безкоштовний канал (Viber/SMS платні). «Акція до 8 березня — всім клієнтам»
  одною кнопкою. Тільки з явною згодою, з лімітами.
- ⚠️ 2026-07-29: розсилка через IG DM — лише клієнтам з opt-in Marketing Messages
  (24h-вікно інакше); без opt-in єдиний канал — Telegram. Деталі —
  `partner-discussion-2026-07-29.md` §7.
- Поля анкети працюють двічі: привід+дата = кваліфікація ліда сьогодні І тригер
  «за тиждень річниця у клієнта Х» наступного року; салону — «минуло 3 тижні»;
  СТО — «сезон шин».
- Сарафан автоматизується через базу: «приведи подругу — знижка» в розсилці.

### 2.6 SEO малих міст (повільний мережевий актив)

«Манікюр Бровари» ніхто не оптимізує — конкуренція мізерна, наш JSON-LD + структура
беруть топ за місяці. Масштабується програмно на сотні тенантів разом — жоден власник
сам не зробить. Потребує власних доменів (міграція на 3minsite.com і так планована).

### 2.7 Self-serve ads helper (опційно, не зараз)

Не агентство. Ми генеруємо креатив + текст + інструкцію «натисни Просунути в IG,
бюджет 100 грн/день». Знімаємо страх кнопки; бюджет і відповідальність — власника.

## 3. Що відкинули і чому

- **Керована реклама за клієнта** — агентська пастка: чужий бюджет, ops-навантаження,
  «винні ми», churn-бомба для тонкомаржинального self-serve.
- **Офлайн QR** як канал — скепсис власника.
- **Чеклист GBP/IG-bio** як головна відповідь — у багатьох клієнтів уже є і GBP, і IG.
- **Visitor-facing AI-бот** (модуль RoxyBo) — AI відповідає клієнтам → ризик вигаданих
  цін; наша ставка — живий власник + швидкий канал (2.3).

## 4. Гейти і порядок

1. **R7 чинний: банер перший, код потім.** Кандидати меседжів A/B: «заявки в Telegram»
   / «щоб знаходили в Google» / «сайт, що збирає базу твоїх клієнтів» / «відповідай
   клієнтам прямо з Telegram».
2. Після сигналу попиту — порядок ланок за залежностями:
   **2.3 TG-loop** (закриває петлю відповіді, відкриває канал) → **2.1 review engine**
   (їде на каналі 2.3) → **2.2 поля анкети** (data-зміна) → **2.4 база UI** →
   **2.5 розсилка**. 2.6 SEO — паралельний повільний трек після доменів.
3. Позиціонування (уточнення R8): не «сайт за 3 хвилини», а **«машина клієнтів:
   сайт + заявки + база + повторні продажі»**. Сайт — засіб, база — актив.
