## 1. Фото: чому san.team.tennis отримав AI-картинки

Факти (file:line у звіті агента; ключове):

- Імпорт IG: перші 20 у порядку стрічки, **жодного ранжування** (`lib/ig/deep.ts:164-175`).
- Sharp-аналіз якості (розмиття/темрява/розмір) **рахується і викидається**
  (`lib/media/import.ts:73-83`, `deep.ts:203-216` — `PhotoMeta` не має поля warnings).
- Vision-аналіз (`analyze-photo.ts`) НЕ має полів: центрованість об'єкта, вгорілий
  текст/стікери, колаж/мем, різкість. Єдині сигнали — `textHeavy`, `useOnSite`.
- Hero = вибір моделі, фолбек — **`eligible[0]` = перше фото зі стрічки** (`generate.ts:451`).
- Тригер AI-генерації — тільки «нуль фото» (`publish.ts:117-118`). Два механізми, як
  20 фото стають нулем:
  1. **`sanitizeMedia` all-or-nothing**: одна невалідна схема → `{photos: []}`
     (`media.ts:253-255`); залежить від `NEXT_PUBLIC_SUPABASE_URL` — розсинхрон префікса
     тихо стирає всі фото.
  2. Vision позначив спортивні пости (текст на банерах, розклади, рахунки) як
     `useOnSite:false` → фільтр `onboard/route.ts:191-192` викинув усі.

**Роботи (WAVE-A, «фото-вет»):**

1. `analyzePhoto`: додати поля `siteQuality: 0-10`, `subjectCentered: bool`,
   `burnedText: bool` (текст/стікери/колаж НА зображенні — відмінне від `textHeavy`
   OCR-сенсу), `heroCandidate: bool`. `PhotoMeta` — `.passthrough()` схема, міграція
   не потрібна (`media.ts:227-245`).
2. Донести sharp-warnings до `PhotoMeta` (зараз викидаються) — безкоштовний сигнал.
3. Відбір 12 (`onboard/route.ts:191-197`): сортувати за `siteQuality` замість порядку
   стрічки; hero-фолбек — найкращий `heroCandidate`, не `photos[0]`.
4. `sanitizeMedia`: per-photo drop замість all-or-nothing (лог кожного викинутого).
5. Тригер генерації: замість «нуль фото» — «менше N=3 придатних (`siteQuality≥5`)»;
   і НІКОЛИ не генерувати, якщо придатних ≥3 (скарга власника — генерація була зайва).
6. Паралельність: аналіз уже йде по 4 (`IMPORT_CONCURRENCY`) — «паралельна модель»
   власника фактично є; додаємо їй правильні питання, не нову інфраструктуру.
7. Фікс-заодно: `tenants.brand` не зберігає `photoMeta` → редакторська регенерація
   втрачає всі сигнали (`publish.ts:179-181`, `edit/actions.ts:282-291`). Зберігати.

## 2. Hero: чому однаковий

- Каркас має **рівно один hero** без структурних ступенів свободи
  (`sections.tsx:25-55`, layout прибитий у `wire.css:152-157`, фото завжди справа).
- Механізм `variants` мертвий: схема+промпт просять модель вибрати варіант
  (`generate.ts:232`), а `salonwireSections` не визначає жодного (`index.ts:36-134`) —
  модель вибирає з порожньої множини.
- Єдина посіяна вісь — hue. Композиція не сіється взагалі.

**Роботи (WAVE-B, «варіанти hero»):**

1. 3–4 структурні варіанти hero у каркасі: `split` (нинішній), `mirror` (фото зліва),
   `full-bleed` (фото тлом + оверлей), `stacked` (центрований, фото знизу) — це CSS+
   markup у wireframe, стилі поверх пише генерований sheet як і зараз.
2. Оживити `variants` для salonwire (механізм уже існує в реєстрі й валідаторі).
3. Посіяти вибір: seed з `designNonce` дає ДЕФОЛТ варіанта, модель може перекрити з
   обґрунтування контенту (фото погане → не full-bleed). «Згенерувати ще раз» крутить
   і композицію, не тільки hue.
4. Той самий підхід далі на 2–3 секції (services: grid/list; gallery: masonry/strip).

## 3. Кольори: чому погані

- Hue-якір — рівномірний 0–360 **без огляду на нішу** (`wire-style.ts:77-79`):
  пекарня може отримати фіолет/кислотний зелений, і промпт прямо забороняє відкат до
  типової палітри ніші.
- Стиль-бриф — 3 рядки без vertical hints/brand voice (`publish.ts:139-147`), у той
  час як текстова генерація їх отримує → два bakery-брифи майже ідентичні.
- Контраст-ремонт **вбиває хрому** (снап у чисті ч/б, `css-contrast.ts:133-141`);
  `transparent` парситься як чорний (`:58-61`) → текст «освітлюється» до невидимості.
- Аудит упереджений до pass і реген іде з тим самим hue (`style-audit.ts:109`).

**Роботи (WAVE-C, «палітра»):**

1. Hue-якір per-vertical: у `lib/verticals` додати `hueRanges` (пекарня: теплі 20–60°
  + акценти; СТО: 200–260°; generic: широкий), seed вибирає всередині діапазону.
   Verticals = data — без зміни коду генерації.
2. Бриф стилю збагатити: vertical label + personaHint + brand voice + список секцій.
3. Контраст-ремонт: зберігати хрому (рухати lightness по OKLCH, chroma зменшувати
   пропорційно, не в нуль); `transparent` — виключити з парсингу як колір.
4. Реген після fail — з НОВИМ hue у межах діапазону ніші.
5. Промпту стилю — обмеження: «2 базові + 1 акцент, узгоджена насиченість».

## 4. Секції й анімації

- 17 секцій у реєстрі; `switchback` і `richText` рекламуються моделі й **безумовно
  викидаються** (`generate.ts:532,546`) — спалені слоти. Прибрати з документа моделі
  або підключити.
- Motion: нуль. `css-lint` уже пропускає `@keyframes` — дозволено, але не просимо.

**Роботи (WAVE-D, «жвавість»):**

1. У wireframe: скролл-reveal через CSS `animation-timeline: view()` з
   `prefers-reduced-motion` фолбеком — БЕЗ JS; плюс базові hover-transitions у wire.css.
2. Промпту стилю дозволити/попросити 1–2 делікатні анімації (fade-up секцій, hover
   карток) — лінт уже їх пропустить.
3. `switchback`: або варіант секції в каркасі (текст/фото зигзаг — він уже є в
   wire.css `--wire-split-order`), або чесно прибрати з реєстру.
4. Мапа: до запиту embed додавати `facts.city` (потрібен окремий шлях — в
   `mapSchema.address` місто дописувати не можна, реквізит копіюється 1:1;
   варіант: окреме приховане поле `mapQuery`, яке будує код).

## 5. Порядок і оцінка

| Хвиля | Що | Розмір | Ефект |
|---|---|---|---|
| A фото-вет | analyze-фікси + ранжування + sanitize per-photo + тригер | ~1 день | прибирає найгіршу скаргу (зайві AI-картинки, погані фото на hero) |
| C палітра | hue-діапазони + бриф + контраст-хрома | ~0.5 дня | «кольори погані» |
| B hero-варіанти | wireframe-варіанти + seed | ~1 день | «однакові сайти» |
| D анімації + switchback | CSS-motion + чистка реєстру | ~0.5 дня | «жвавість» |

Рекомендований порядок: **A → C → B → D** (болючість для конверсії тесту попиту).
Кожна хвиля — окремий агент + рев'ю + живий скріншот-прогін двох контрастних ніш
(пекарня і СТО) до/після.

> Перехрес: журнал №45 (wireframe-only — план НЕ повертає вибір шаблонів; варіанти
> живуть УСЕРЕДИНІ одного каркаса), №44/§4.8 (жодних сфабрикованих інтер'єрів у
> генерованих картинках — vetting це не змінює), інваріант 1 (усі фото в Storage).
